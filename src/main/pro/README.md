# 定制功能接入

业务代码分别位于 `src/main/pro`、`src/renderer/pro`、`src/shared/pro`。
后续功能在这三个目录内按业务命名，不再增加 `pro-业务名` 目录。
开发与同步约束见仓库 `.agents/skills/pro/SKILL.md`。

源码、运行时命名空间和设置页统一使用 Pro；数据库使用 `ProFeatures.db`，
待恢复文件使用 `ProFeatures.restore.db`，恢复前备份保存在 `pro-backups`。

## 英雄池

- 主窗口侧栏「英雄池」，路由 `/pro/champion-pool`。
- 玩家来自当前客户端、已打开的玩家页、搜索历史和本地缓存。
- 手动同步当前服务器的最近 100 / 200 / 500 / 1000 场。遵循战绩页的 SGP/LCU 偏好；SGP 不支持时使用 LCU，认证未就绪或网络错误不会静默切换数据源。
- 按服务器、PUUID、gameId 去重；已缓存内容可在客户端断开后查询。账号/服务器切换会终止当前同步，取消保留已完成页面。
- 筛选队列、位置、日期、版本、英雄，支持指标排序、分页、常用英雄图、按 10 / 20 / 50 场分页的完整缓存战绩，以及战绩页同款 Akari 对局卡片。
- 使用独立 `ProFeatures.db`，版本 1 保存玩家和战绩，版本 2 增加英雄/队列资料缓存。上游 `LeagueAkari.db` 及其迁移不变。
- 默认分析单排/双排，最多读取最近 10,000 场缓存；超出时页面明确提示，不能视为完整生涯统计。
- 排除重开；胜率排除未知胜负；KDA 为逐场比值的平均，零死亡单独记录为排除样本。补刀/分、伤害占比分别统计有效样本，伤害占比要求五名队友数据完整。LCU 缺失可靠位置时标为未知，不猜测。
- 继续复用 Akari 的 Naive UI、主题、ChampionIcon、MatchCard 和玩家战绩页。打开战绩页只传其支持的英雄和位置条件；本页其余筛选留在 KeepAlive 状态。
- 英雄与队列资料优先使用 LCU；无客户端时使用 CommunityDragon，资料缓存进入定制库。头像使用其公共图片 URL 与浏览器 HTTP 缓存，首次加载需要网络，并非完整离线资源包。展开卡片时按需获取额外对局数据；需要客户端与对应数据源可用，不自动持久化时间线。
- 不直接导入 RiftMind 的旧库；保留上游的开局自动跳转行为。

## 英雄手册

- 主窗口侧栏「英雄手册」，路由 `/pro/notebook`；不需要账号或战绩即可创建笔记、连招、对阵经验、出装与加点方案。
- 首屏按英雄显示卡片，支持名称/拼音/ID 搜索、仅看已记录及最近更新/笔记数量排序；进入英雄后再按类型、对手、正文筛选。卡片统计在主进程聚合全部条目，不受笔记分页限制；资源不可用时仍可通过英雄 ID 进入已有手册。
- 新建按类型展开，提供笔记/连招/对阵/出装的可选写作模板（仅填充空正文）；所有类型可复制，详情可直接编辑。英雄 ID 保存在路由查询参数，支持返回、前进及英雄池/复盘深链接。
- 独立库版本 3 增加条目、不可变历史修订与资源目录缓存。搜索标题/正文、置顶、按英雄与类型筛选；条目每页 30 条，历史每页 20 条。
- 保存和恢复使用事务及预期修订号；并发冲突保留编辑内容，可另存为新条目。历史恢复产生新修订；删除进入回收站，可恢复，不永久清除内容。
- 连招使用游戏图标与可排序步骤；出装支持有序分组、数量、复制与逐级加点。点击英雄池战绩卡片上方「从此对局创建方案」生成待确认草稿；结算栏不冒充购买顺序，缺时间线时不猜测加点。
- 「赛前速查」只读取选人阶段的本人英雄与公开对手，置顶优先；断线、取消选人、切号、换英雄会清理旧结果。速查不覆盖编辑草稿，不执行连招；客户端装备方案由手册中的显式应用或用户启用的选人同步规则管理。
- UI 复用 Naive UI、ChampionIcon、ItemDisplay、SummonerSpellDisplay、LcuImage 和主题。首次获取完整英雄/装备/技能资源需要网络，缓存目录可离线使用，图片仍依赖浏览器缓存。
- 未保存编辑在本窗口 KeepAlive 页面切换时保留，不作为已持久化笔记；重启后仅保证已保存内容恢复。

## 对局复盘与个人主页

- 打开现有复盘页时，直接从本局报告及本地个人历史基准生成最多三个「本局关注点」，不新增页面、分析按钮、后台拉取或数据库表。历史读取复用个人基准的同英雄请求；切换报告、停用页面时忽略旧请求结果。
- 关注点包括连续快照内不超过五分钟、至少下降 500 金币的最大对位经济差变化；低于个人下四分位数的补刀；死亡后 60 秒内的资源事件；对线经济落后及高于个人上四分位数的死亡频率。它们是可复查的观察，不作失误或因果判定；没有命中项时不展示空卡片。
- 历史结论至少需要五场有效样本，沿用同账号、服务器、英雄、位置、队列、版本及分析版本的历史筛选与对局去重。历史不可用时仍显示本局观察；缺失时间线不补值。点击关注点同步事件范围与曲线指标，补刀对照复用现有两局对比并对齐时间点。

- 独立库版本 4 增加 `ReviewReports` 和 `ProfileSnapshots`，不改变已有英雄池、手册数据或上游库。
- 英雄池每场对局上方「复盘此局」生成报告；侧栏「对局复盘」查看已保存报告、分页并选择两份报告对比。复用 Akari 对局卡片、游戏图标与 Chart.js。
- 报告保留原始结算、原始时间线、分析版本、服务器和玩家标识；相同输入复用报告，重新获取到不同输入时创建不可变的新报告。网络失败不覆盖已有报告；首次无时间线时只生成明确标注缺失的结算报告。
- 10/15 分钟使用目标之前不超过 60 秒的最近快照，不插值、不补零。对位只接受峡谷经典模式、双方同位置唯一匹配；LCU 缺可靠位置则不计算对位差。曲线缺帧处断开。
- 死亡、建筑与大型野怪事件可定位到游戏时间、原始帧/事件索引和可用的位置坐标。默认前后一分钟、可调整为 15–600 秒的窗口展示快照变化、击杀和装备事件；这些是观察数据，不推断因果或完整争夺过程。
- 时间点心得直接保存为英雄手册笔记，附带不可变报告 ID、时间与可选事件 ID。手册里可跳回复盘；沿用手册搜索、置顶、修订恢复与回收站。
- 「个人主页」通过现有 LCU `getCurrentRankedStats` 获取当前账号段位；连接账号、段位事件、结算后防抖采集，也可手动记录。每次成功采集保存完整段位响应与召唤师快照，即使段位没变也保留此次观察。失败不写假值，切号/换服务器/退出时作废旧请求。
- 当前已集成接口没有可验证的带日期 LP 历史序列；接口给出的上赛季结算/最高段位在现有 `RankedTable` 中单独展示。历史表分页显示本地观察时间、赛季、队列、段位、LP、胜负和触发来源，不能将两次观察的差值宣称为某一局的加减分。
- 记录只在 Akari 与客户端连接时发生，关闭应用期间不能补录。快照按服务器与 PUUID 隔离，离线可查看已记录账号。没有新增自动操作客户端或第三方接口。
- 个人页曲线与明细按赛季、单双排/灵活排位筛选。图表读取所选赛季的全部精简记录，表格分页不会截断曲线；同一时刻或段位未变的记录也保留。横轴按记录顺序等间距排列，段位轴仅表达实际段位顺序，不将大师、宗师和王者换算成虚构 LP 门槛。悬停/点击点位或点击明细时间可查看每次段位、LP 与上一条记录的变化；跨段位同时显示前后段位，变化不是单场得失分。
- 缺少赛季编号的记录单独归入「赛季未知」，不猜赛季、不跨记录计算差值；未定级/定级中的曲线断开，原始快照仍在明细中。此功能直接查询版本 4 的快照，不新增数据库迁移。
- 个人页活动概览复用定制库内按账号、区域隔离的对局记录，展示近 30 天对局数、活跃天数、时长、胜负，以及按本地自然日排列的 30 天对局热力图。每格代表一天，按 0、1–2、3–5、6–9、10+ 场分级；悬停、点击或键盘聚焦可查看日期、胜负和时长。空格只表示无已同步记录，跨月和夏令时按自然日处理。重开不计入，未知胜负及缺失时长保留样本说明；不重复提供英雄池、战绩列表或心得编辑，战绩入口直接打开上游页面。首屏不展示采集机制的蓝色说明提示。

## 训练、导入导出与备份

- 定制库版本 5 添加练习状态、训练目标、批量复盘任务、装备同步规则与回执；版本 1–4 通过事务升级，失败不清库。
- 手册支持标签搜索、核对版本、关联条目及待练习/练习中/已掌握状态。练习保留当时的条目修订号；正文变化后需重新确认，保存仍检查并发修订。
- 所有文件操作统一在「设置 → Pro」：按全部/单个英雄导出手册 JSON、导入预览及冲突替换、选择方案导出客户端装备 JSON、完整定制库备份与恢复。文件选择由主进程原生对话框完成，renderer 不接收任意文件路径或数据库操作能力。
- 手册 JSON 限制 4 MiB、1000 条；省略账号及对局来源，关联条目重新映射，缺失关联计入预览。相同内容去重，同名不同内容默认新增；明确替换时保留原条目的历史修订并检查预期版本。
- 手册仍保留「应用到客户端」及按英雄/地图启用的选人同步。只在大厅或选人阶段操作，使用现有 LCU 连接；同步核对账号、服务器、进程、选人状态、条目修订和客户端方案指纹。客户端冲突可创建副本或明确覆盖；超时后再次应用会先回读确认，避免重复创建。LCU 没有条件写入契约，外部软件在最终检查与 PUT 之间修改仍存在竞争窗口，需要真实客户端验证。
- 单场复盘的个人基准选取同账号、队列、位置、版本、分析版本的此前最近 20 场报告，默认同英雄，可包含其他英雄。有效样本至少 5 场才显示中位数及四分位数；缺失不补零。10 分钟落后、资源事件前 60 秒死亡展示发生次数并链接到证据时间，不把时序相关当作因果。
- 训练目标保留创建时的基准样本，独立于后续重新分析；新样本取创建后同范围最近 20 场。支持草稿、开始、暂停、完成、结束；样本不足的目标保持草稿。进度和样本可以打开原报告。
- 「训练中心 → 批量复盘」分页选择已缓存战绩，预览已有/待准备项目，主进程顺序获取详细报告。取消、切号、退出、失败保留逐项结果；再次继续仅处理未完成项，应用重启将遗留运行中任务标为中断。需要时间线的数据仍受 LCU/SGP 可用性约束。
- 事件复盘可调整观察窗口；敌方打野只按可靠位置字段及实际击杀/助攻参与者标识，不猜测未公开位置。
- 备份通过 SQLite 一致性快照导出；恢复校验完整性、版本和表结构，只接受版本 4–5 的定制库，最大 1 GiB。恢复在下次启动、业务初始化前执行事务替换，并先保存 `pro-backups/before-restore-*.db`。失败保留当前库与候选文件；恢复后关闭自动装备同步，需用户重新启用。上游库不参与恢复。

## 上游接入清单

除三个 pro 目录外，只有以下接入：

- `src/main/bootstrap/index.ts`：主进程注册。
- `src/renderer/src-main-window/shards/index.ts`：主窗口 renderer 注册。
- `src/renderer/src-main-window/routes/index.ts`、`components/sidebar/Sidebar.vue`：路由和导航；侧栏忽略空菜单值，避免菜单状态同步清除当前查询参数。
- `src/renderer-shared/i18n/index.ts`：定制翻译合并。
- `src/renderer/src-main-window/components/settings-modal/SettingsModal.vue`：仅挂载 Pro 标签，具体设置组件留在 `renderer/pro/main-window/settings`。
- `electron.vite.config.ts`、`tsconfig.web.json`、`vitest.config.ts`：renderer 别名及类型检查范围。

同步上游时按 pro skill 的普通 merge 流程操作，重点核对这些接入点，以及 Shard、IPC、SGP/LCU 和 GameResourceProvider 契约。
双库只隔离业务表结构，不能替代版本兼容检查或安装包更新渠道隔离。

## 检查

通常运行 `yarn typecheck`、`yarn test`、`yarn build`。
SQLite 集成测试必须使用匹配本地原生模块 ABI 的 Electron；普通 Node 测试运行会显式跳过这些测试。
在仓库根目录执行以下跨平台命令运行所有定制测试：

```sh
node -e "require('node:child_process').spawnSync(require('electron'), ['node_modules/vitest/vitest.mjs', 'run', 'src/main/pro', 'src/renderer/pro', 'src/shared/pro'], {stdio:'inherit', env:{...process.env, ELECTRON_RUN_AS_NODE:'1'}}).status === 0 || process.exit(1)"
```

集成测试使用独立临时库，验证持久化、带数据升级、升级失败回滚、新版本拒绝、分页去重、取消、账号隔离及资料缓存。
renderer 测试验证旧请求不能覆盖新玩家、页面停用后停止轮询且返回保留筛选。
窗口检查应使用独立测试 userData；测试数据不可写进用户的正式数据库。
真实 LCU/SGP 同步和 Windows 安装包仍需相应环境验证。

## 体验增强（数据库版本 6）

- 主窗口标题栏接入 `ExperienceTools`：Ctrl/Cmd+K 搜索英雄、访问历史、手册、报告和设置。没有新增页面。
- `experience` 主进程模块在连接与结算后增量归档当前账号最近最多 200 场基础战绩。已有缓存跳过；结算记录尚未出现时最多追加两次延迟检查。时间线仍由复盘操作按需获取。失败页重试保留已提交页，账号切换禁止提交旧请求。
- `ExperiencePreferences`、`ExperienceWorkspaces`、`ExperienceScenes` 均在定制库。恢复状态包含定制路由、玩家、筛选、分页和报告查询参数；按账号及区域隔离，离线保留最近使用账号。设置可关闭恢复与自动归档。游戏开始时上游切入的对局页不被恢复覆盖。
- 预设保存自动接受、点赞、再来一局、自动匹配，以及辅助/OP.GG 窗口的自动显示设置。应用调用上游 SettingFactory 的公开设置能力；失败时补偿恢复，不能保证跨库/外部副作用原子性。当前设置不匹配已保存预设时显示“自定义”。
- 主页从缓存推导最近连续游玩记录，两局间隔超过 2 小时视为新的一次；重开单独计数。段位变化仅使用同赛季的已观察快照，不能推算单局加减分。
- 常玩搭档表示至少两次同队，不推断预组队关系。最多分析最近 10,000 场缓存，保留截断提示；共同对局分页读取。
- 分享卡使用 Canvas 生成独立 PNG，通过主进程原生保存对话框或剪贴板输出。默认没有账号标识，英雄池分享可明确选择包含名称。
- 顶部任务浮层汇总连接、归档与批量复盘状态；重试跳过已完成部分，保留页面已加载内容。批量复盘仍需用户原有操作触发。
- 版本 1–5 通过事务迁移至 6，备份/恢复包含体验数据，并支持旧备份与旧版已暂存的恢复文件升级。测试与窗口冒烟使用隔离 userData。
